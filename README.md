# Деканат будущего — концепт личного кабинета студента

Работающий прототип «цифрового деканата будущего»: расписание, успеваемость, заявки на справки, уведомления и кабинет сотрудника — в одном месте, с телефона и компьютера.

> ⚠️ Это **концепт для конкурса**, а не официальный сервис вуза. Все люди, оценки, зачётки и документы **вымышленные**.

## Быстрый старт

```bash
npm install
npm run seed   # создаёт data/db.json с вымышленными данными
npm start      # http://localhost:3000
```

## Что внутри

- **Вход и профиль** — сессия, показ/скрытие пароля, профиль студента (ФИО, факультет, направление, курс, группа, зачётка).
- **Главная** — приветствие, ближайшая пара, кольцо среднего балла, счётчик дней до сессии, активные заявки, быстрые действия.
- **Расписание** — сегодня и неделя (листается на ±4 недели), аудитории и преподаватели, заметные пометки о переносах/отменах/заменах.
- **Успеваемость** — идущие баллы текущего семестра с прогресс-барами, история прошлых семестров, средний балл.
- **Заявки и справки** — подача онлайн (4 типа), таймлайн статусов «Принята → В работе → Готова», уведомление о смене статуса, место получения.
- **Уведомления** — дедлайны, переносы, новости деканата; счётчик непрочитанных.
- **Кабинет сотрудника** — очередь заявок всех студентов, продвижение статуса одной кнопкой (студент сразу получает уведомление).
- **Оформление** — светлая/тёмная тема (системная + ручной выбор), mobile-first, нижняя навигация на телефоне, скелетоны загрузки, пустые состояния, тосты.

## Как устроена безопасность

- Пароли хранятся только как **bcrypt-хеши** (`seed.js`), в открытом виде нигде нет.
- Сессия — `httpOnly` + `SameSite=Strict` cookie; секрет сессии берётся из переменной окружения `SESSION_SECRET` (в коде секретов нет; без переменной генерируется временный при старте).
- **Разделение данных на сервере**: API никогда не принимает id студента от клиента — данные отбираются по `req.session.userId`, поэтому чужую заявку/оценки не открыть даже подстановкой адреса.
- Мутации (POST/PATCH) проверяют заголовок `Origin` (анти-CSRF вместе с SameSite=Strict).
- Примитивный rate-limit на вход: 5 неудачных попыток → пауза 1 минута.
- Базовые заголовки: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`.
- Весь пользовательский текст экранируется на клиенте (`esc`) — защита от XSS.

## Стек

- Node.js + Express + express-session + bcryptjs — бэкенд и API.
- Хранилище — JSON-файл `data/db.json` (атомарная запись через временный файл). Легко заменяется на PostgreSQL/MongoDB при масштабировании: вся логика доступа к данным сосредоточена в `server.js`.
- Фронтенд — ванильные HTML/CSS/JS (без сборки): современные возможности платформы (`color-scheme`, `light-dark()`, `prefers-color-scheme`, safe-area insets, `:user-invalid`, контейнерные/медиа-запросы).

## Структура

```
server.js      — API, сессии, авторизация, отдача статики
seed.js        — генератор вымышленных данных (аккаунты, расписание, оценки)
data/db.json   — «база данных» (создаётся скриптом seed)
public/
  index.html   — каркас: экран входа + оболочка приложения
  styles.css   — дизайн-система, тёмная тема, mobile-first
  app.js       — SPA: роутинг, рендер разделов, работа с API
```

## Деплой для жюри

Подходит любой хостинг Node.js, доступный из РФ (Render, Railway, reg.ru, Timeweb, VPS и т.п.):

```bash
SESSION_SECRET=<случайная-строка> npm start
```

Для HTTPS за прокси дополнительно выставьте `COOKIE_SECURE=1`.
